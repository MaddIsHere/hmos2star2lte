# Patches

Every folder in `patches/` is one patch: `patch.json` describes what it adds to the images, `files/` holds
its binaries (sources in `src/`), an optional `hook.py` edits files taken from the OTA itself.
Generated by `tools/gen_patch_docs.py`.

## 00-core

**Core: preinit, fstab, access_token**

Core for every device: hmos-preinit as /init (maps the HarmonyOS partitions, kernel log to the cache partition), the second-stage fstab written from devices/<name>/device.json, access_token_id permissions. The device kernel and boot.img are passed on the command line. Always installed.

init commands:

- `post-fs-data: mkdir /data/vendor 0771 root root`
- `post-fs-data: mkdir /data/vendor/tmp 0770 root root`
- `post-fs-data: chown access_token access_token /dev/access_token_id`
- `post-fs-data: chmod 0666 /dev/access_token_id`


## 10-display-decon

**Display: Samsung DECON composer + ION buffer allocator**

Replaces Huawei's Kirin display HALs with a composer that presents the client target through the Samsung DECON window-config ioctl on /dev/graphics/fb0 (the S9+ kernel has no DRM/KMS), and a dma-buf allocator on Samsung ION. Without it the panel is switched off when composer_host closes fb0. Build the two libraries with build/build_ohos.sh. It also sets persist.sys.graphic.GpuApitype to 0 (OpenGL): the OTA default 1 (Vulkan) makes render_service call a null Vulkan function pointer at its first frame (the Huawei Vulkan ICD cannot create a device on a Mali-G72) and crash-loop.

Files added to /vendor:

- `lib64/libdisplay_composer_vdi_impl.z.so`
- `lib64/libdisplay_buffer_vdi_impl.z.so`
- `etc/param/star2lte_graphic.para`

ueventd:

- `/dev/kmsg 0666 0 0`
- `/dev/ion 0666 0 1003`
- `/dev/graphics/fb0 0666 0 1003`

init commands:

- `pre-init: setparam persist.sys.graphic.GpuApitype 0`
- `post-fs-data: mkdir /data/local/tmp 0777 root root`
- `post-fs-data: chmod 0777 /data/local/tmp`
- `post-fs-data: chmod 0666 /dev/kmsg`
- `post-fs-data: chmod 0666 /dev/ion`
- `post-fs-data: chmod 0666 /dev/graphics/fb0`
- `post-fs-data: chown system system /sys/class/backlight/panel/brightness`
- `post-fs-data: chmod 0666 /sys/class/backlight/panel/brightness`


## 11-gpu-mesa

**GPU: Mesa software rendering (softpipe) for OpenGL ES**

Mesa 26 softpipe as the system EGL/GLES driver (the S9+ Mali blobs are bionic and unusable). Frames are rendered on the CPU and copied into the window dma-buf. The Huawei Vulkan ICD is removed so render_service stays on GLES. Build with build/build_mesa.sh.

Files added to /vendor:

- `lib64/chipsetsdk/libEGL_impl.so`
- `lib64/chipsetsdk/libGLESv1_impl.so`
- `lib64/chipsetsdk/libGLESv2_impl.so`
- `lib64/chipsetsdk/libGLESv3_impl.so`
- `lib64/chipsetsdk/libgallium-26.1.0-devel.so`
- `lib64/chipsetsdk/libexpat.so.1`

Removed from /vendor:

- `etc/vulkan/icd.d/vulkan_driver_v200.json`

ueventd:

- `/dev/ion 0666 0 1003`

init commands:

- `post-fs-data: chmod 0666 /dev/ion`


## 15-no-crash-reboot

**No reboot when a service crashes**

HarmonyOS reboots the phone when SceneBoard crashes 4 times in 4 minutes, and init reboots it when a 'critical' service (render_service, foundation, samgr, ...) keeps crashing: it first stops every service and unmounts /data, so with the kernel refusing the reboot the phone is left dead. On a port a missing driver is enough to trigger this. The SceneBoard policy is switched off and the critical flag is cleared for every system and vendor service (system ones are re-declared in /vendor, system.img is not rebuilt): crashed services are simply restarted.

init commands:

- `pre-init: mount none /vendor/etc/sweet/ams_service_config.json /system/etc/ams_service_config.json bind`

Hook: `hook.py` (edits files taken from the OTA).


## 20-userauth-no-tee

**Lock screen without TEE (swipe to unlock)**

sweet has no iTrustee: Huawei's user_auth CA library blocks forever and the lock screen asks for a PIN that was never set. This stub answers 'no credentials enrolled' so the lock screen is swipe-only. PIN/fingerprint/face cannot be enrolled.

Files added to /vendor:

- `lib64/libuserauth_daemon.z.so`


## 21-huks-software

**Software key store (HUKS without TEE)**

Replaces the TEE-backed HUKS CA library with OpenHarmony's HUKS core on OpenSSL (software root key). Needed by account, settings and app data encryption services.

Files added to /vendor:

- `lib64/chipsetsdk/libhuks_ca_hdi.z.so`


## 37-kirin-daemons-off

**Kirin-only vendor daemons off**

Huawei vendor daemons that only talk to Kirin hardware (touch THP, ISP and sensorhub logs, Balong modem, HiSilicon battery management, NPU, TEE/RPMB, DDR inspection, USB Type-C port, power control, media) are not started any more. On sweet they crash in a loop, eat CPU and fill the log. Their init files are removed from vendor.img, and the Kirin camera daemon (whose binary is not in this port) from chip_prod.img. Their init cfgs also wait up to 5 s each for Kirin device nodes that never appear (about 25 s of boot time): those waits are removed.

- `etc/init/bms_logcat.cfg`

- `etc/init/bms_thermal.cfg`
- `etc/init/ddr_inspect.cfg`

- `etc/init/hiai_server.cfg`

## 41-chipset-vsync-stub

**render_service: stop polling the Kirin camera vsync service**

render_service looks up the camera HAL's chipset_vsync_service on every frame until it finds it. On sweet it never exists, so that cost a failed HDI lookup about 30 times a second. A small replacement libchipset_vsync reports it as connected once and ignores the updates.

Files added to /vendor:

- `lib64/libchipset_vsync_sweet.z.so`

init commands:

- `pre-init: mount none /vendor/lib64/libchipset_vsync_sweet.z.so /system/lib64/libchipset_vsync.z.so bind`


## 46-pin-lock

**PIN / password lock screen without TEE**

Huawei's user_auth and pin_auth HDI services keep credentials in their TEE (iTrustee), which sweet does not have: a PIN could be set but the lock screen stayed swipe-only. They are replaced by OpenHarmony's own REE implementation (drivers_peripheral user_auth 3.0 / pin_auth 2.1, OpenHarmony-5.1.0-Release, Apache-2.0), which keeps the PIN data salted and hashed in /data/service/el1/public/{pinauth,userauth}. The user_auth service is built against the OpenHarmony 5.0 IDL of user_auth v3.0, the one HarmonyOS 5.x uses (no VerifyAuthToken): with the 5.1 IDL Huawei's stub called the wrong methods and the lock screen asked for a PIN that was never set.

Files added to /vendor:

- `lib64/libuser_auth_interface_service_3.0.z.so`
- `lib64/libuser_auth_driver.z.so`
- `lib64/libpin_auth_interface_service_2.1.z.so`
- `lib64/libpin_auth_driver.z.so`


## 50-remove-setup-wizard

**Remove the setup wizard (skip first-boot setup)**

Removes HwStartupGuide from system.img (the original files are saved next to the output in removed/) and marks the first-boot setup as done in the settings database. Use it while WiFi does not work: the wizard cannot be completed without a WiFi connection.

Files added to /vendor:

- `bin/sweet-oobedone`

Removed from /system:

- `system/app/HwStartupGuide`
- `system/etc/noticeFile/HwStartupGuide_OpenSource.html`

init commands:

- `post-fs-data: start sweet_oobedone`

init services:

- `/vendor/bin/sweet-oobedone`

Hook: `hook.py` (edits files taken from the OTA).
